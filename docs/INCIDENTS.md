# INCIDENTS — 장애 탐지와 대응 기록

## 탐지 규칙

| 규칙 | 값 |
|---|---|
| 장애 열림 | 같은 점검이 연속 2회 실패 (시작 시각 = 첫 실패) |
| 장애 닫힘 | 다음 정상 응답, 또는 점검이 설정 필요로 바뀜 |
| 분류 | 실제 서버 장애 / 인증 문제 / DNS·네트워크·프록시 제한 / 측정 불가 |
| 표시 | 상단 상태 줄 경보 수, 개요 경보 띠, 장애 화면(분류·상태 필터), 타임라인, 실패 로그 |

## 기록

### 2026-11-22 · `/metrics` 미배포를 장애로 잘못 표시 (CLOUD OPS 결함, 수정됨)
- **발견:** 운영 주소로 3회 수집했을 때 `실시간 지표 (/metrics) 연속 3회 실패` 경보가 계속 떠 있었다.
- **원인:** 404(미배포)를 측정 불가 실패로 세어 장애를 열었다. 이후 "설정 필요"로 바꾸자, 이미 열린 장애는 성공 보고가 오지 않아 닫히지 않았다.
- **조치:** `/metrics` 404는 설정 필요로 처리하고, 설정 필요로 바뀐 점검의 장애는 닫도록 했다. 회귀 테스트 2개 추가.

### 2026-11-22 · 실시간 Worker 버전 차이를 경고로 잘못 표시 (CLOUD OPS 결함, 수정됨)
- **발견:** 운영 수집에서 전체 상태가 "주의", 버전 `c2fbc3f ≠ 6c9fa62`.
- **원인:** 원본은 Worker 코드가 바뀐 배포에서만 Worker를 다시 배포한다(원본 DEPLOYMENT.md v60). 이 차이는 정상이다.
- **조치:** 프런트엔드와 API 사이의 버전 차이만 경고하고, Worker 버전은 설명으로 표시. 회귀 테스트 2개 추가.

### 2026-11-22 · 숨은 탭에서 첫 데이터가 오지 않음 (CLOUD OPS 결함, 수정됨)
- **발견:** 브라우저 창이 숨겨진 상태에서 열자 "첫 수집 결과를 기다리는 중"에서 멈췄다.
- **원인:** 숨은 탭은 폴링을 쉬는데, 첫 요청까지 쉬고 있었다.
- **조치:** 첫 요청은 항상 보내고, 탭이 다시 보이면 즉시 새로 받는다.

### 2026-11-22 · 주소에 계정 정보가 있으면 데이터를 못 받음 (CLOUD OPS 결함, 수정됨)
- **발견:** `http://user:pass@host/`로 연 화면이 "지표 서버에 연결하지 못했습니다"를 표시했다.
- **원인:** 브라우저는 계정 정보가 든 주소에서 상대 경로 `fetch`를 거부한다.
- **조치:** 요청 주소를 `location.origin` 기준으로 만든다.

## WINTERLIGHT 운영 장애

2026-11-22 수집 범위(로컬 대시보드, 약 5분)에서 운영 서비스 장애는 관측되지 않았다. 대시보드가 배포되어 계속 수집하기 전까지는 이 기록이 운영 전체 기간을 대표하지 않는다.
